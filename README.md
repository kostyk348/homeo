Компактное ядро (137 строк, без зависимостей) для балансировки **конкурирующих
инвариантов** в пространстве политики. Порт с C++ (CIDHC, `include/homeo/`).

Вместо "обучать поведение" контроллер каждый тик пере-балансирует набор
инвариантов под текущее состояние среды и возвращает коэффициенты политики
(все координаты нормализованы к `[−1, 1]` и разворачиваются в осмысленные
величины: доли посадок, агрессивность продаж, темп найма и т.п.).

## Как это работает

Поведение задаётся инвариантами `I_j(X)` с весами `w_j(X)`:

```
E(X) = Σ_j w_j(X) · |I_j(X)|^p_j      →  min
```

- **вес может зависеть от состояния или от самого X** (аналитическая функция:
  sigmoid, clamp, кусочные, степенные — никакой нейронки). Так реализуются
  "surrender"-переходы: пока угроза мала, инвариант цели доминирует; выросла —
  перевесил инвариант отступления, и точка равновесия плавно смещается.
- **минимизация** — градиентный спуск (Adam) + термальный шум CLT `(12·U−6)`
  с annealing `T_t = T0·2^(−k·t)` (как в `relaxer.hpp`).
- **численный градиент** через центральные разности автоматически учитывает
  `dW/dX` — само-вес: если вес инварианта зависит от X, минимум не обязан
  совпадать с нулём инварианта, и градиент это честно находит (см.
  `test_self_weight`).

## API

```python
from homeo import HomeoEngine, make_invariant, make_dynamic_invariant

eng = HomeoEngine(
    center=[0.5, 0.5], range_=[0.5, 0.5],          # X0 ∈ [0, 1] каждая
    invariants=[
        make_invariant(1.0, 2, lambda X: X[0] - 0.4),          # цель 0.4
        make_dynamic_invariant(1.0, 2,                          # surrender:
            lambda X: X[1] - 1.0,                              #   "наступать",
            lambda X: 1.0 - threat),                           #   вес падает с угрозой
    ],
    lr=0.2, max_iter=40, grad_tol=1e-4, t0=0.01, seed=42)

eng.set_raw([0.1, 0.1])   # тёплый старт от текущей политики
eng.tick()                # релаксация до сходимости (≤ max_iter шагов)
x = eng.raw()             # развёрнутые коэффициенты политики
```

### Примитивы

| Объект | Назначение |
|---|---|
| `Invariant(weight, p, err, wfn)` | инвариант: `err: X→float`, `wfn: X→float` (по умолчанию 1.0) |
| `make_invariant(weight, p, err)` | статический вес |
| `make_dynamic_invariant(weight, p, err, wfn)` | вес зависит от X / состояния |
| `HomeoEngine(center, range_, invariants, ...)` | релаксация политики |
| `HomeoEngine.tick()` | один проход Adam до сходимости (возвращает число итераций) |
| `HomeoEngine.set_raw(raw)` / `.raw()` | нормализация `[−1,1]` ↔ развёртка |
| `HomeoEngine.reset()` | сброс моментов Adam |

### Сходимость: контракт и измеренные числа

Тесты проверяют свойство, а не «функция вернула что-то». Контракт:

1. **Корень внутри ящика** `[−1,1]^n` → `tick()` завершается досрочно
   (`iters < max_iter`), и найденная точка совпадает с аналитическим минимумом с
   точностью ≤ `1e-3` по нормированной координате (0.1 % ширины ящика).
2. **Корня внутри ящика нет** → движок не рапортует о сходимости: `iters == max_iter`,
   точка упирается в границу, остаточная энергия велика.
3. **Оптимум ровно на границе** — законный случай: сходится досрочно, `E = 0`
   (граница не путается с несходимостью).
4. **`grad_tol` абсолютен в единицах `E`**: масштабируете веса на λ — масштабируйте и
   допуск, тогда ни точка, ни признак не меняются (проверено на λ от `1e-4` до `1e4`).

Набор, на котором это измерено: 40 случайных квадратичных задач с известным
аналитическим минимумом (2 координаты, веса 0.5…2, старт в пределах 90 % ящика), тот же
набор с термальным шумом `t0=0.02`, 8 задач с динамическими весами (`x* = (1−t)·a + t·b`),
нелинейная задача с весом `w(X)=X²` (корень `4x³+2x−1=0` считается бисекцией прямо в
тесте), граничные и запредельные цели, 5 масштабов весов.

## Пример на реальной системе: демпфированный осциллятор

`examples/driven_oscillator.py` — не демо «чаша», а измеримая система с эталоном:

```
m·x'' + c·x' + k·x = F0·cos(ω·t)   →   x(t) = A·cos(ω·t − φ)

A = F0 / sqrt((k − m·ω²)² + (c·ω)²)      [м]
φ = atan2(c·ω, k − m·ω²)                 [рад]
```

`A` и `φ` — измеряемые величины (амплитуда по датчику перемещения и сдвиг фаз между силой
и перемещением). Ядро не получает ни одной из этих двух формул: оно получает два УРАВНЕНИЯ
НЕВЯЗКИ в ньютонах — подстановку анзаца `x = A·cos(ωt − φ)` в уравнение движения с
приравниванием коэффициентов при `cos` и `sin`:

```
r1(A, φ) = (k − m·ω²)·A − F0·cos φ      [Н]
r2(A, φ) = −c·ω·A + F0·sin φ            [Н]
```

и само находит точку, где обе невязки нулевые. Эталон в примере двойной, чтобы проверка не
опиралась на одну и ту же выкладку: (1) замкнутая формула выше; (2) независимое численное
интегрирование того же ОДУ методом Рунге—Кутты 4 (только stdlib) — от покоя до установившегося
режима, с измерением `A` и `φ` проекцией `x(t)` на `cos`/`sin`.

Вывод `python examples/driven_oscillator.py` (сокращённо):

## Область применимости (честные ограничения)

1. **Решение обязано лежать внутри ящика** `center ± range`. Если его там нет, движок не
   сходится и сообщает об этом ровно одним способом: `tick()` возвращает `max_iter`.
   Отличить от законного граничного оптимума просто: посмотрите на `energy()` — на границе
   при достижимом оптимуме она нулевая, при недостижимом велика (для осциллятора с ящиком
   `A ≤ 0.3·A*`: `iters = 300/300`, `E = 0.16`, ошибка 40 %).
2. **`grad_tol` абсолютен в единицах `E`** — это ловушка при работе с весами. Замер: веса
   `1e-3` при `grad_tol = 1e-4` дают «сошлось» за 36 шагов, но на 2.3 % мимо аналитического
   минимума (`raw = 2.773` вместо `3.0`). Нормируйте веса к O(1) (как в примерах) или
   масштабируйте `grad_tol` вместе с весами — тогда ни точка, ни признак не зависят от λ
   вообще (проверено на λ от `1e-4` до `1e4`).
3. **Точка зависит от шага `lr`** (таблица в разделе «Сходимость»). «Сошлось» означает
   «в пределах достигнутой точности», а не «заморожено»: второй `tick()` сдвигает точку
   примерно на `2e-4` (в raw) при `lr=0.03` и на `2e-3` при `lr=0.1` с шумом `t0=0.02`.
4. **Метод локальный.** Adam + термальный шум: при невыпуклой сумме инвариантов глобальный
   минимум не гарантирован. Все гарантии тестов — для задач, где минимум единственный или
   известен.
5. **Цена.** Градиент считается центральными разностями: `2n` вычислений `E` на шаг, каждое
   `O(m)` по числу инвариантов, `tick()` — до `max_iter` шагов. Замер: `n=2`, `m=2` → 153 шага
   за 0.66 мс (~1.1 мкс на вычисление `E`). Для больших `n` дешевле был бы аналитический
   градиент — ядро его не требует, но и не предоставляет.

## Боевое применение

Ядро используется в агенте для Kaggriculture (kaggle): `HomeoPolicy` балансирует
6 коэффициентов (плотность посадок wheat, melon, найм рук, агрессивность
продаж, инвестиции в гусей/коров) с инвариантами-фазами сезона:
`plant_rate → target_plant(t)`, `sell_eagerness → давление shed`,
`hire_rate → потребность в руках` и т.д. — средний доход агента ~21k на сид
(бенчмарк v4 — 13.7k).
